AI 第二大脑工作台
个人旗舰项目 · AI 产品设计 & 全栈开发 · 2026.07 – 至今
13 周 / 17 版迭代 · 以下为完整项目内容
19+功能模块
1500+真实数据条
3 条自动化工作流
17 版迭代版本

一个把「自我调试」做成产品的系统：记录 → 抽离 → 定位 → 修复 → 迭代。产品直觉不是假设出来的，是从 1500+ 条真实行为记录里长出来的。核心方法论：面对 AI，要有自己的判断——所以我给内容管线加了 4 道过滤。

核心方法论 · 4 道内容过滤闸门

闸门 1
素材黑名单
剔除 AI 合成类素材源，不让 AI 喂养 AI。
闸门 2
水位线 T
只消化上一周期之后的新内容，不重复捕获陈旧信息。
闸门 3
信息四分类
强制分类：事实 / 数据 / 观点 / 推断，置信度透明。
闸门 4
dry-run 演习
推送前用历史周跑一遍验证稳定性，发现退化立即停推。

4 个亮点场景 · 不拼功能数量，每一张都在讲产品判断

① 全貌 · 19 模块在一个 SPA产品入口
左侧导航 + 主区切换，本地 IndexedDB + 云端多端同步。设计判断：19 个模块不是想到一个加一个，是按「我怎么理解生活」切出来的——分组本身就是个产品决策。
② 时间轴 · 粘贴即落库每日最常用
一行文本直接落到对应小时，无表单无选择器。设计判断：记录摩擦越低越好，不该让工具本身成为负担。
③ AI 日报 · 自动推送 + 成本可控每日 20:05
token 用量实时监控 + 模型降级链（3 级 fallback）。设计判断：LLM 不能黑盒跑，必须有 token 预算 + 模型切换 + 失败告警。
④ 认知吸收卡 · 4 道闸门的实际生效处核心差异化
GitHub 周榜 → AI 消化 → 认知吸收卡。前面 4 道闸门就是这个卡片的实际生效位置——不是嘴上的方法论，是跑通了 13 周的机制。

求职时投递状态散落在日历（测评 DDL）、邮箱（投递记录）、聊天记录（HR 进度）、备忘录（面试复盘）里，全乱。市面求职追踪器（Jobsync、THRIVE 等）大多是欧美流程：没有测评笔试、没有内推、没有网申 DDL、没有届别窗口——而这几样恰恰是中国校招的主干。所以我把默认状态机做成中国校招，社招 / 考公用户一处配置即可切换。

三个视图 · 一份档案 · 产品判断藏在默认值里

① 今日帖 · 该投的 / 该催的 / 该备战的每日首页
打开第一屏只回答一个问题：「今天该干什么」。每条带行动按钮（投了 / 催一下 / 去备战），右侧投递总览 + 近 7 天新增。设计判断：追踪器的价值不是记录全，是「此刻该做什么」够明确。
② 牌阵 · 六态流转 + 拖拽推进核心交互
想投 → 已投 → 笔试 → 面试 → 已转生 → 淬殒。拖一张牌到下一列即推进，自动写历史记录；流程 / 公司 / 月历三种视角切换。点开一张牌即翻档案：公司 / 岗位 / 城市 / 渠道 / 薪资 / 简历版本 / 届别核验 / 适配度 / 下一步动作，DDL 倒计时超时自动标「需跟进」。设计判断：求职本身够焦虑了，界面要做的是把它变成「可摆弄的牌」。
③ 试炼 · 面试复盘长成题库闭环设计
每轮面试记下「被问倒的题」，自动汇成按公司筛选的刷题库；被问倒的题可让 AI 生成答题思路（要点式 + 面试官为什么问）。设计判断：失败也要变成资产，复盘不是写完就死的笔记。
④ 三视图一屏看 · 单文件能扛多少工程取舍
今日帖 / 牌阵 / 试炼三个视图、六态状态机、月历与法定节假日标注，全部装进一个 HTML 文件：0 构建、0 依赖、离线双击可用，GitHub Pages 直接发布。设计判断：工具不能比它解决的问题还重。

设计过程 · 从需求定义到视觉定稿

  • 需求定义一页纸：先写清问题、用户、边界与「不做什么」，再动手——避免边做边漂移。
  • 信息架构页面地图：今日帖 / 牌阵 / 试炼三页职责划分，页面地图先行，不堆功能。
  • 花札（HANAFUDA）考据 + 视觉规范 v1：牌面隐喻、术语（添牌 / 撕牌 / 牌阵 / 转生）与视觉一致；牌背从风格样品 v3-v5 到候选 v6-v9 共 9 版迭代。
  • 竞品拆解：Jobsync / THRIVE 等欧美流程追踪器的缺失项（测评 DDL、内推、网申窗口、届别）即差异化清单。

工程取舍

  • 单文件 HTML：0 构建、0 依赖、离线双击可用；GitHub Pages 直接发布，换电脑靠导出 / 导入搬家。
  • 数据自主：数据存浏览器本地，JSON 备份 / 迁移 + CSV 导出分析；BYO Key——AI 功能自带 Key，只存浏览器 localStorage，不进仓库、不经过任何服务器。
  • 演示模式：一键载入虚构数据先看效果，可一键清空，降低试用门槛。
