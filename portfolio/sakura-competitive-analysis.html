报告目的：回答三个问题——①市面上的求职追踪工具都怎么做的？②樱帖的差异化机会在哪？③下一步该做什么、按什么顺序做？

一、分析背景与范围

产品定位：樱帖是一款面向中国校招求职者的单文件求职追踪工具，核心解决"投递状态散落各处、面试备考缺乏体系"的问题。

分析时间：2026 年 9 月（产品设计阶段，v1 上线前）

分析方法：功能对比矩阵 + 核心流程走查 + 商业模式拆解 + 差异化机会识别

竞品筛选逻辑

不是所有"找工作 APP"都是竞品。按"与樱帖解决同一问题的程度"分三层：

直接竞品 国内主流

解决同一问题，用户重叠度高

实习僧：国内校招主流平台，含投递记录功能

牛客网：笔面试题库 + 求职进程追踪

间接竞品 海外工具

产品形态最接近，但市场不同

Huntr：欧美求职看板工具，拖拽 Kanban 形态

Teal：欧美职业管理平台，含岗位追踪 + 简历管理

同类独立项目 个人开发

本土化尝试，形态相近

秋招航海志：抖音博主个人项目，本地化状态机 + AI

替代方案 用户现状

用户现在用什么

Excel / 备忘录 / 日历：灵活但无体系，靠人工维护

各竞品体验断点

实习僧

✅ 岗位资源丰富，投递自动记录

❌ 投递记录是列表不是看板，无法拖拽

❌ 无面试复盘、无题库、无提醒体系

❌ 数据锁在平台内，无法导出

牛客网

✅ 题库是全行业最强，面经社区活跃

❌ 没有投递追踪功能，投递和备考是割裂的

❌ 面试复盘靠社区发帖，非个人结构化记录

Huntr / Teal

✅ 看板交互成熟，数据分析专业

❌ 状态机是欧美流程（无笔试、无内推、无网申 DDL）

❌ 免费版功能受限，高级功能需订阅

❌ 全英文界面，国内用户有门槛

秋招航海志

✅ 本土化到位，AI 功能丰富

❌ 需本地部署 + 自配 API Key，上手门槛高

❌ 未开源，仅群分享，无法验证代码质量

❌ 无提醒、无数据导出

关键发现：欧美工具（Huntr/Teal）已经验证了"求职追踪工具可以收费"的商业模式，且客单价不低（$19-24/月）。国内市场目前没有纯求职追踪的付费产品——实习僧和牛客都是靠招聘服务/题库赚钱，追踪只是附属功能。这意味着樱帖如果做到足够好用，未来有商业化空间。

五、差异化机会分析

樱帖的独特价值（别人抄不走的）

  1. 中国校招全流程状态机：想投→已投→笔试→面试→已转生+落樱旁路，这是欧美工具永远不会做的，国内平台又不屑于做的"中间地带"。
  2. 单文件零部署：打开链接即用，不注册、不下载、不依赖后端。对比秋招航海志要装环境配 Key，樱帖的上手门槛是零。
  3. 数据完全自主：localStorage 本地存储 + 导出备份，求职数据不被任何平台锁定。这在"数据隐私"越来越受关注的当下是差异化卖点。
  4. 投递→复盘→题库 闭环：面试中被问倒的题自动汇成按公司分类的题库，面试前直接刷。牛客题库虽强但和投递记录割裂，樱帖是唯一打通的。
  5. AI 备考辅助（BYO Key）：答题思路 + 盘下一轮 + 面经收题，用户自带 Key 不花平台的钱，也没有平台抽成。

六、结论与迭代建议

核心结论：樱帖不需要"大而全"，要守住"中国校招 + 零部署 + 数据自主 + 备考闭环"四个差异化支柱，在此基础上补齐 AI 简历对版和打招呼话术两个高频缺口。

迭代优先级（按 ROI 排序）

P0
AI 简历对版（JD 匹配度分析）——粘贴 JD → 对照简历给出匹配度 + 短板建议 + 微调方向。用户最高频痛点，Teal 验证了付费意愿，樱帖已有岗位↔简历对应的数据基础。
P0
AI 打招呼话术生成——岗位卡一键生成 BOSS 直聘打招呼语。高频动作，秋招航海志已验证需求，实现成本低（一次 API 调用）。
P1
岗位雷达自动化——把现有面经采集管道扩展为岗位资讯采集，每日定时抓目标公司官方校招页，推送增量岗位。这是所有竞品都没有的差异化王牌。
P1
面试复盘 AI 增强——复盘写完后 AI 自动整理成题卡 + 给出改进建议。已有复盘功能，加 AI 是自然延伸，和"被问倒的题自动进题库"形成闭环。
P2
数据可视化增强——在现有大数条基础上加投递趋势图、各阶段转化率漏斗、公司分布饼图。Huntr 的数据分析是付费点，樱帖可以免费提供作为差异化。
P2
团队/共享功能——求职搭子之间共享岗位信息、互相提醒。远期功能，v1 不背这个包袱。
P3
多端同步方案——单文件架构的天然限制，可通过云端备份（可选）缓解。不是核心需求，用户主要在电脑上用。

一句话定位（对外传播用）

樱帖 = 中国校招版 Huntr + 牛客题库的个人版 + 零部署单文件
不注册、不下载、数据在自己手里，从投递到面试复盘一个文件搞定。
