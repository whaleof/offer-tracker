# Offer Tracker · 秋招作战板

**一个 HTML 文件，管住你从投简历到拿 offer 的全过程——零部署、零注册、数据在自己手里。**

👉 [直接使用（GitHub Pages）](https://whaleof.github.io/offer-tracker/) · 下载 `index.html` 双击也能用

## 为什么做

秋招投到第 8 家的时候，我的状态是这样的：测评 DDL 在日历里，投递记录在邮箱已发送里，面试进度在跟 HR 的聊天记录里，复盘在备忘录里——全乱。

市面上的求职追踪器（Jobsync、THRIVE、JettZgg/jobtracker）几乎都是欧美流程：没有测评笔试、没有内推、没有网申 DDL、没有届别窗口。而这几样恰恰是中国校招的主干。

所以自己做了一个：默认状态机就是中国校招（待投递 → 已投递 → 测评/笔试 → 面试中 → Offer / 挂了），社招、考公的人可以在代码里一处配置改成自己的流程。

## 面试官你好

点「载入演示数据」直接试玩——**数据是假的，体验是真的。** 不用注册、不用登录，所有数据只存在你自己的浏览器里。

## 功能

- **状态看板**：六态流转，拖动/一键推进，同状态多次进出自动记历史
- **岗位卡片**：公司/岗位/城市/渠道/薪资/简历版本/下一步动作/备注
- **DDL 倒计时**：≤3 天红、≤7 天橙，超时未推进自动标「需跟进」
- **漏斗统计**：投递 → 测评 → 面试 → offer，每层转化一眼看清
- **数据自主**：localStorage 本地存储，导出/导入 JSON 备份与跨设备迁移
- **演示模式**：一键载入脱敏虚构数据，体验完整功能

## 改造成你自己的流程

代码按 `CONFIG / STORE / VIEWS / UI / IO / DEMO` 分区，顶部有修改指引：

- 加/改状态列 → 只改 `CONFIG.STAGES`
- 加岗位字段 → 只改 `CONFIG.FIELDS`
- 数据结构变更 → `CONFIG.DATA_VERSION` +1，在 `STORE.migrate` 写迁移

## AI 协作开发故事

这个项目从立项到上线约 1 天，全程与 AI 协作完成。分工是：**我负责定义**——痛点拆解、竞品调研（扒了三个开源竞品的 README 与提交记录，确认差异化在中国校招状态机）、单点功能取舍、每轮验收与 QA 清单；**AI 负责实现**——写码、自测、修复。

开发纪律来自我另一个长期迭代的项目（一个 19 模块的个人工作台，13 周迭代 17 版）：

- 数据层先写冒烟测试（8 用例：增删改/状态历史/迁移/空兜底），改一处跑一遍
- 状态比较时机、重绘丢光标、用户输入炸 `onclick`——三类常见前端坑在交付前自查修掉
- **真实投递数据永不进公开仓库**，演示数据全部脱敏虚构

难的不是写码，是定义「做一个什么」——这也是这个项目想证明的事。

## 隐私

- 代码在 GitHub，数据在你的浏览器（localStorage），本页无后端、无上报、无统计脚本
- 仓库与演示数据中均无任何真实投递记录
