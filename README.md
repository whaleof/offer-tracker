# 樱帖 · 秋招作战版

> 一个 HTML 文件，管住你从投简历到拿 offer 的全过程——零部署、零注册、数据在自己手里。

👉 [在线使用](https://whaleof.github.io/offer-tracker/) · 或下载 `sakura.html` 双击打开

> **2026-09-09 起主产品为樱帖（`sakura.html`）**：添牌 / 拖拽推阶段 / 撕牌删除都在樱帖内完成。旧作战板（列表式 UI）已退役，代码存档在 `归档备份/`（不进仓库），根目录 `index.html` 仅作跳转页。

## 它解决什么问题

求职时，投递状态散落在日历（测评 DDL）、邮箱（投递记录）、聊天记录（HR 进度）、备忘录（面试复盘）里，全乱。

市面上的求职追踪器（Jobsync、THRIVE 等）大多是欧美流程：没有测评笔试、没有内推、没有网申 DDL、没有届别窗口——而这几样恰恰是中国校招的主干。樱帖的默认流程就是中国校招：**想投 → 已投 → 笔试 → 面试 → 已转生**，另有一条旁路 **落樱**（没走通）。社招、考公的用户可以改代码换成自己的流程（见「自定义」）。

## 功能

全站三页：**今日帖 / 牌阵 / 试炼**。

### 今日帖 —— 牌桌概览

- **转生进度条**：已转生占全部牌的比例
- **该投**：存了还没投的
- **该催**：投了 7 天没音讯的（自动筛出来，不用自己算日子）
- **面试**：在流程里的
- **最近翻开的牌**：最近动过的几张，一键跳牌阵
- **投递总览**：总在阵 / 进行中 / 面试 / 已转生的计数
- **雷达盒**：提示"该补雷达了"，或直接从这里合并新岗

### 牌阵 —— 六态卡牌看板

三种看法可切换：

- **流程**：横看推进，拖着牌到下一列就算推进一步；点牌翻档案
- **公司**：一家一张牌，按已投 / 未投分组，点组头可收起
- **月历**：阶段推进、截止日、约面时间自动摆上历；拖条目到其他日期可改投递日，点条目翻那张牌的档案

每张牌的档案里有公司 / 岗位 / 城市 / 渠道 / 简历版本 / 下一步动作 / 备注，可一键推进到下一阶段、也可**撕牌**（删除前二次确认）。

### 试炼 —— 面试与备考

- **面试复盘**：每轮记"被问啥 / 卡哪 / 下轮改啥"
- **题库**：内置 22 道种子题；备忘里单独记下"被问倒的题"，会自动汇总进个人题库
- **备战清单**：可勾选的待办

### 其它

- **新手引导**：第一次打开自动弹 30 秒引导（三步上手 + 术语小词典 + 数据安全提示）；右上角「? 帮助」随时重看
- **导入表格**：Excel 直接复制粘贴 / CSV 文件 → 自动认列（可手改）→ 同指纹去重后落牌，老记录一次搬进来
- **到点提醒**：右上角「🔔 提醒」授权后，该催（投出 7 天）、今天面试、3 天内截止会弹浏览器系统通知（每天最多一次，纯本地不依赖服务器）
- **流程预设**：右上角「流程」一键切校招全流程 / 社招精简（无笔试列），只换显示不动数据
- **演示模式**：`?demo=1` 一键载入虚构数据，先看效果再决定要不要用
- **雷达合并**：把雷达产出的 JSON 拖进牌阵即可批量导入（同指纹去重，只加不动）；点「合并雷达」有说明弹层讲 JSON 怎么来
- **云端备份（可选）**：部署到服务器时才生效；访问令牌由使用者在本机填写，不写在源码里

## 岗位雷达（配合外部脚本）

页面负责**合并与去重**，**抓取**由独立脚本完成——两边通过一份 JSON 交接：

```
radar.py   读求职画像 → 联网搜岗 → 规则打分排序 → 输出增量 JSON
                              ↓
              拖进牌阵 / 点「合并雷达」导入
                              ↓
                按指纹去重 → 只加新牌，绝不动已有牌
```

- **打分规则**在脚本里：红线岗位一票否决、意向方向加分、城市加减分、毕业时间窗口判定、来源权重、临近截止加分。
- **去重靠指纹**：公司 + 岗位 + 城市归一化后的哈希。所以同一条岗位反复导入，不会变成两张牌。
- 页面上的「合并雷达」「导入表格」是外部数据的两条入口；「合并雷达」会先弹说明讲清 JSON 从哪来，不会跑脚本的用户走「导入表格」一样能批量进来。

> **现状与边界**：抓取环节目前需要人工触发（跑脚本），**尚未做成后台定时服务**。这是路线图上最想补的一块。

## 快速开始

1. 打开[在线链接](https://whaleof.github.io/offer-tracker/)，或下载 **`sakura.html`** 双击打开
   （注意是 `sakura.html`，不是 `index.html`——后者只是跳转页，单独下载打不开）
2. 第一次打开会有 30 秒新手引导（三步上手 + 术语小词典），右上角「? 帮助」随时重看
3. 已经用 Excel / 备忘录记了投递？牌阵右上角「**导入表格**」直接粘贴（Excel 里 Ctrl+C → 这里 Ctrl+V）或选 CSV 文件，自动认列、同指纹去重，一次全搬进来
4. 不想录入，点「先用示例牌看看样子」载入演示数据；有雷达产出的 JSON 也可以拖进牌阵批量导入

> 提示：数据存在浏览器本地，**清缓存前请先导出备份**——页脚的「导出备份 / 导入备份」随时可用（见「数据与隐私」）；牌攒到 5 张还没导出过时，樱帖会提醒你存一份。

## 流程预设（校招 / 社招）

右上角「流程」一键切换，只换牌阵的列和推进路径，牌的数据原样保留、随时切回：

- **校招全流程**：想投 → 已投 → 笔试 → 面试 → 已转生（＋落樱旁路）
- **社招精简**：想投 → 已投 → 面试 → 已转生（无笔试列；数据里存有「笔试」状态的牌会折到「面试」显示，切回校招即复原）

考公等特殊流程暂未内置，可在代码顶部 `STAGE_DEFS` 里改列名。

## 自定义

想深度改流程，动 `sakura.html` 顶部的 `STAGE_DEFS` / `REAL_STATUS`（9.13 起阶段体系改为预设驱动，`STAGES` 数组由 `rebuildFlow()` 按当前预设生成）：

代码在文件里按 `① 存取层 / ② …` 分区，每区开头有注释说明这一区负责什么；文件顶部注释写了该区的修改指引。

## 数据与隐私

- 数据存在**你自己浏览器的 localStorage**（键 `job-tracker-v1`）。无账号、无统计脚本、不联网上传。
- **本仓库不包含任何真实个人数据**：`数据/` 已整目录加入 `.gitignore`，仓库里的演示数据均为虚构。
- 云端备份是可选功能：只有部署到自己的服务器、并在本机填了令牌之后才启用。
- **跨设备迁移（2026-09-13 起内置）**：页脚「导出备份」把牌 + 题库存成一个 JSON 文件（不含云端令牌）；「导入备份」可选**覆盖式**（整包替换）或**增量合并**（同「雷达合并」的指纹纪律：公司+岗位+城市 只加不动）。
