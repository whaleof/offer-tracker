二、樱帖功能对照（现在有什么 / 缺什么）

阶段现状现在实际谁在做关键缺口
① 准备缺AI 对话 + 独立卡无「我的素材库」入口（简历/作品集/定位句集中管理）
② 找岗部分AI 对话届别核验、企查查风控、适配度分层打分这三件每次都散在对话里，没进樱帖；雷达只负责「拉新岗」，不负责「这岗我能不能投」
③ 对版部分AI 对话「这岗用哪份简历」自动建议、多版本简历库、一键按 JD 微调——这是你最高频痛点，樱帖只有手动挂件
④ 投递有AI 记录 + 你点缺「投递凭证」留存（官网链接/邮件底稿/BOSS 对话截图）；「已投」与「成功提交」未区分
⑤ 跟进部分AI 巡检巡检在樱帖外跑；樱帖内漏斗/月历空态导航不可见（P0 bug），且催办不主动弹
⑥ 备战伪/不全AI 生成闪卡有；但「深度分析/个人画像/BOSS 话术」你反馈没实现、没体验过；缺按公司归属的真题库（你要求带公司标签）
⑦ 落地缺独立卡杭州线完全独立，未并入求职主流程

三、必做 / 高频功能清单（按你的真实行为排序）

你现在每天真在用的（高频 · 必保）

  • 今日作战首页＝「今天该投哪个 + 对应简历在哪」。你明确认可，v9.2 其实没有真正的「今日帖」，新设计已定名「今日帖」但还没做成上线版。
  • 岗位雷达（自动搜岗增量）＝sakura-radar + 「合并雷达岗位」按钮，每天 07:30 跑，是最高频入口。
  • 简历 ↔ 岗位对应＝「这岗用哪份简历 / 要不要改定位句」。你 9/9 还在逐份加定位句，是头号高频痛点。
  • 状态推进 + 漏斗＝已投→测评→笔试→面试→转生，你靠它看「卡在哪」。

你设计里要、但还没体验的（中频 · 等面试才有用）

  • 面试闪卡 / 复盘 / 话术——逻辑在，但还没真实面试数据喂进去。
  • 按公司归属的真题库 + AI 按 JD 生成备战（v2 路线：AI 生成 + 联网搜经验帖合流）。

四、AI（我）做不到的事 + 原因 + 解法（诚实边界）

做不到为什么解法
自动投简历 / BOSS 批量打招呼账号在你手机需扫码登录；反自动化风控严，封号＝求职期灾难；岗位动态加载你点「投递」，我备文案+记录；v2 接云服务器做「点更新直拉」，但绝不代投
实时读 BOSS 状态 / 已读回执BOSS 不开放 API、反爬设计为「自行记录」模式：投完你在樱帖记一笔；每日巡检按规则提醒催办
面试 / 薪资谈判 / 线下动作必须本人到场我备题库、话术、反问模板；你上场
公司底细实时核查（企查查）企查查连接器当前断开；非实时结构化WebSearch 核实 + 把常用几家预核查存进岗位卡；或接企查查连接器
跨设备云同步樱帖当前 localStorage 单文件，换设备丢v2 接云服务器（密钥只存服务器，不进仓库）
语音播报当前环境无 TTS图示 + 结论前置 + 短句；或用 Edge「朗读」
「投递成功」回读确认提交动作须本人（承诺动作）你提交后，我把成功页信息写进樱帖该岗位
一句话总结边界：凡是「动你账号 / 替你承诺 / 要实时爬第三方」的动作，我都做不了；凡是「信息整理 / 生成文案 / 按规则提醒 / 本地记录」的事，我都能做且已在做。樱帖的定位应该是「你的求职外脑 + 记录中枢」，不是「自动投递机器人」。
